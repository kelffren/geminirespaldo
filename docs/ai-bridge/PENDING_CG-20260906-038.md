### PROBLEM
Kelo's current avatar presentation intentionally separates the physics root/collider from the visible sprite, but the generic prop occlusion system still decides whether an actor overlaps a prop using only `actor.radius`. That radius is a gameplay collider proxy, not the visible avatar rectangle. The discrepancy already exists at visualScale 1.15 and becomes larger if the avatar is increased to 1.20x. This can produce a state where the sprite visibly intersects a tree/fountain/front prop while the occlusion system does not clip/redraw because the smaller physics circle has not entered the prop bounds yet.

### CONFIRMED_IN_GEMINI
Current `main` is 0184be1bc378baee67f7dacfc5f030d9903e1fdf. `index.html` remains V6.33 and loads `engine-ab.js` before the late environment/system wrappers.

`engine-ab.js::presentationOf()` defines separate presentation geometry: `physicsRootX/Y = p.x/y`, `colliderRadius = p.radius`, `footRootY = p.y + 10`, and visual dimensions derived from `AVATAR_VISUAL_SCALE = 1.15`. For lateral facing the base visual width is 48; for front/back it is 54; base visual height is about 81. At 1.15 the resulting dimensions are approximately 55x93 world/CSS-space units before world zoom. The lateral sprite therefore extends about 27.5 units to either side of the foot root and roughly 83 units upward from `p.y`, while a typical physics radius of 20 only represents +/-20 around the physics root.

`src/environment/generic-props.js::overlaps(actor,b)` uses only `actor.radius || 20`: `actor.x+r > b.x`, `actor.x-r < b.x+b.w`, and the analogous Y tests. Both `actor-base-y-clip-v1` and `actor-base-y-redraw-v1` call this physics-circle-derived overlap before deciding whether to clip/redraw the actor/prop. The clip rectangle itself also uses `actor.radius` (`r = max(22, actor.radius + padding)`) rather than the visual presentation bounds.

`src/environment/prop-contract.js` supplies `visualBounds` and occlusion metadata for generic props, including the Plaza fountain and nature props. Therefore the prop side already has visual-space metadata; the actor side of the overlap contract is the part still using collider geometry.

At a hypothetical 1.20 visual scale, lateral dimensions become about 58x97 and front/back about 65x97, while the physics radius remains unchanged. Thus increasing avatar scale would enlarge the region that can visually intersect props without enlarging the current occlusion trigger.

This is separate from collision correctness. Keeping collision independent from sprite size is desirable in top-down gameplay. The problem is reusing collider geometry as the visibility/occlusion envelope.

### EXTERNAL_EVIDENCE
Official Unity 2D sorting documentation distinguishes sprite render geometry/pivot/sort point from physics concerns and supports sorting from the sprite Pivot rather than its center. The same documentation describes Y-axis/custom-axis sprite ordering as a rendering responsibility. Unity's SpriteAlignment API explicitly supports bottom-center/custom pivots. Godot's TileSet documentation likewise exposes `Y Sort Origin` as a visual sorting offset for top-down scenes. These are consistent with Kelo's newer footRoot/depthRoot direction: rendering depth should be based on a presentation/sort anchor, not inferred from collider size.

Community evidence also contains the opposite warning: forcing colliders to match visible sprite dimensions can make gameplay collisions inaccurate because transparent/ornamental sprite area is not necessarily physical body area. This supports retaining Kelo's small gameplay collider while introducing a distinct visual occlusion envelope.

### HYPOTHESIS
The correct contract is three separate spatial concepts rather than one radius reused everywhere:
1. `colliderBounds` or physics radius — gameplay collision only.
2. `depthRoot` / footRoot — ordering against props and actors.
3. `visualOcclusionBounds` — conservative visible silhouette/envelope used only to decide whether a prop/actor overlap is worth clipping/redrawing.

If generic prop occlusion uses the avatar presentation rectangle (or a conservative reduced envelope derived from it) for broad-phase visual overlap while preserving `depthRootY`/prop `baseY` for who belongs in front, 1.20x should no longer create additional clipping gaps without changing any gameplay collision.

### RISKS
Using the full sprite rectangle can over-trigger occlusion because transparent pixels and upper-body space are conservative bounds; this may increase redraws.
Changing broad-phase overlap without preserving baseY/depthRoot ordering could make Kelo pop in front of props incorrectly.
Larger visual bounds increase pair checks/redraw opportunities with many actors; performance must be measured.
Aura, nameplates and particles should not automatically expand body occlusion bounds; they have different layering contracts.
If clip masks are enlarged blindly, foreground props may be overdrawn or reveal halos around Kelo.
