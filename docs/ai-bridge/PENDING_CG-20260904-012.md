### PROBLEM
The production hero is visually anchored at `footY = p.y + 10`, while collision/depth candidate logic continues to reason mostly from the physics origin `p.x/p.y` and `radius` (20 for the local player). The current lateral sprite destination is ~48px wide and, with the current 4x4 sheet aspect contract, roughly ~81px tall before world zoom. This means the visible body extends far above the collision circle. Plaza and Gardens use collider-radius overlap tests to decide whether an actor is included in the layered redraw set, then use `actor.y` rather than the rendered foot root to switch front/behind at each landmark `baseY`. Increasing presentation scale to 1.15x/1.25x increases the mismatch without changing collision.

### CONFIRMED_IN_GEMINI
- `engine-a.js` defines localPlayer with `radius:20`; movement/collision resolves a circle around `p.x,p.y`.
- `engine-ab.js` draws the hero from a visible foot root `footY=p.y+10`; the body extends upward by `dh`, and the nameplate is positioned from `footY-dh-6`.
- `src/environment/plaza-depth.js::overlapsFountain(actor)` uses `actor.radius||20` around actor.x/actor.y to decide whether the actor enters the compositing set; `actorInFront(actor)` compares `actor.y > FOUNTAIN.baseY`.
- `src/environment/gardens-landmark.js::overlaps(p)` has the same radius-based candidate logic; `inFront(p)` compares `p.y >= landmark.baseY`.
- Therefore the visual foot currently crosses a baseY about 10 world px before the depth switch based on actor.y. At zoom 1.45 that offset projects to about 14.5 CSS px. This is a coordinate-contract mismatch, not yet a measured visible defect.
- If presentation scale is increased while keeping the foot root fixed, the body/nameplate visual AABB grows upward while the radius-based overlap candidate stays unchanged; head/shoulder intersections with a front layer can occur before the actor is admitted to the special compositor.
- Redundancy/ownership observation: Plaza and Gardens duplicate the same conceptual responsibilities (`overlaps` using radius and `inFront` using actor.y) rather than consuming a shared actor presentation-bounds/depth-root contract. Do not refactor this duplication until an A/B trace proves the contract needed.

### EXTERNAL_EVIDENCE
- PixiJS documents anchors as normalized sprite-relative origins that remain dimension/resolution agnostic when texture or sprite size changes; this supports separating a visual anchor/pivot from the physics center.
- Godot proposal #9222 explicitly identifies center-bottom as the desired origin for many Y-sorted 2D characters; Godot proposal #13428 describes incorrect Y-sorting when the sprite pivot/sort origin does not correspond to the intended bottom/feet point.
- Community top-down 2D reports similarly place character origins/pivots at the feet for predictable Y sorting and note popping/occlusion errors when tall sprites and sort pivots disagree.
- Counterevidence: Kelo World is not using a generic scene-graph Y-sort. Its explicit landmark compositor can intentionally use a different threshold from the feet. A 10px offset may be an authored visual choice. Do not replace it solely because another engine recommends foot pivots.

### HYPOTHESIS
A dedicated presentation contract per actor — `footRoot`, `visualBodyBounds`, `labelAnchor`, and `depthRoot` — will let Kelo scale to 1.15x/1.25x while collision stays radius=20. The landmark compositor should use visual bounds only for redraw/culling eligibility and an explicitly chosen depth root (likely footRoot or footRoot plus authored bias) for front/behind decisions. This should reduce occlusion pops without changing movement or collision.

### PROPOSED_CHANGE
Do not change production first. Instrument a pure helper/probe that derives, for each actor and chosen presentationScale:
1. `footRootX = p.x`, `footRootY = p.y + 10` (baseline contract from current renderer),
2. `bodyRect = {left:p.x-dw*scale/2, right:p.x+dw*scale/2, top:footRootY-dh*scale, bottom:footRootY}`,
3. `labelY = bodyRect.top - 6`,
4. candidate `depthRootY = footRootY` plus optional authored `depthBiasY`.
Then compare the current radius-based compositor against a visual-AABB candidate test while leaving actual draw order unchanged. Only after measurements should a second variant switch the depth threshold from actor.y to the explicit depth root. Preserve collider radius, world position, camera, gait and sprite frame sequence.

### DO_NOT_ASSUME
- Do not assume `footRootY=p.y+10` is artistically final; it is only the current rendered contract.
- Do not assume visual AABB should drive collision.
- Do not assume every landmark needs the same occlusion mask; complex props may need authored front masks/footprints.
- Do not assume a larger actor should move its nameplate proportionally upward forever; mobile readability may require a capped screen-space label gap.
- Do not refactor Plaza/Gardens into a common depth module before the baseline/candidate traces show the same contract works for both.

### EXPERIMENT
Baseline -> probe -> same trace -> re-measure.

A. BASELINE_RADIUS_Y: current code and current output.
B. PROBE_VISUAL_BOUNDS_ONLY: compute bodyRect/footRoot/depthRoot but do not alter compositing; log cases where visual body intersects the front-layer rectangle while current `overlaps*()` rejects the actor, plus cases where footRoot has crossed baseY but actor.y has not.
C. VISUAL_CANDIDATE_SAME_DEPTH: use bodyRect to select actors for redraw, keep current actor.y front/behind threshold.
D. VISUAL_CANDIDATE_FOOT_DEPTH: use bodyRect for candidate selection and explicit footRootY (+ optional measured bias) for depth switch.

Run at presentationScale 1.00, 1.15, 1.25 and zoom 1.05, ~1.22, 1.45. Reproduce slow LEFT/RIGHT passes and diagonals across the Plaza fountain and Gardens east landmark, from both behind->front and front->behind. Include stop/reversal near baseY. Repeat same world traces at 60/90/120 Hz if harness supports refresh control. Keep world movement/collider/camera/gait identical.

### RISKS
- Visual-AABB candidate tests can increase redraw frequency/overdraw, especially at 1.25x and with multiple actors.
- Nameplates are currently rendered inside `renderAvatar`, so special depth redraws also redraw labels; a larger body can make labels participate in occlusion in ways that are visually wrong. A future separation of body vs label pass may be needed, but do not do it blindly.
- Using footRoot exactly at baseY may expose asset-specific alignment errors; some props may need `depthBiasY`.
- Enlarging the sprite without adjusting culling margins may reveal additional landmarks with the same issue outside Plaza/Gardens.
