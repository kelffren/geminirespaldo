## CG-20260905-017

- status: NEEDS_BENCHMARK
- tags: [movement, lateral, foot-planting, reversal, avatar-scale, mobile, desktop, pages, playwright, audit]

### Problema
El auditor integral `scripts/live-hero-audit.mjs` había quedado desfasado respecto al contrato vivo de locomoción lateral: seguía exigiendo `release frame = 0` aunque `engine-ac.js` usa actualmente `plantFrame = 2` y `plantPhase = 0.5` por defecto. Además, el auditor no cache-busteaba `engine-ac.js`/`engine-ah.js` y no tenía un workflow LIVE dedicado que lo ejecutara, por lo que podía validar código visual/gait obsoleto o quedar huérfano.

### Confirmación en Gemini
- `engine-ac.js` mantiene `MOV-plant-frame-v1` con `DEFAULT_PLANT_FRAME = 2`, `LATERAL_PLANT_PHASE = frame / 4`, avance de gait por distancia mundial real y auditoría `MOV-plant-audit-v1`.
- En release estable, la fase se fija al plant phase, el visual frame queda en plant frame y `strideDistancePx` vuelve a 0.
- `engine-ab.js` mantiene la separación entre presentación y física: escala visual 1.15x, collider independiente, foot root y visual bounds separados.
- `engine-ah.js` mantiene hard-stop de presentación separado de las velocidades físicas.
- El `live-hero-audit.mjs` previo codificaba `release frame = 0` y no exigía el contrato actual de reversal/plant.
- No existía un workflow dedicado que ejecutara `scripts/live-hero-audit.mjs` en pushes relevantes.

### Evidencia externa
- MDN documenta que `requestAnimationFrame()` normalmente sigue la frecuencia de refresco del display (60/75/120/144 Hz) y recomienda basar progreso en tiempo en lugar de contar callbacks; esto respalda mantener gait desacoplado del número de frames de pantalla.
- MDN documenta que `CanvasRenderingContext2D.imageSmoothingEnabled=false` conserva bordes nítidos al escalar pixel art; esto será relevante antes de aumentar más el tamaño visual del avatar.
- Aseprite permite definir/exportar pivots de slices en JSON, una alternativa más robusta a inferir continuamente el apoyo de pies desde la silueta alfa.
- Feedback comunitario de pixel art coincide en que foot sliding suele ser un problema de timing/contacto/arco del pie, y que añadir movimiento secundario no corrige por sí solo un contacto mal sincronizado.

### Hipótesis
Antes de experimentar con más bob, lean, brazos o una escala visual mayor, el cuello de botella más seguro era volver confiable el gate integrado que mide simultáneamente locomoción lateral, reversal, release plant, collider/foot-root y escala en móvil y escritorio.

### Cambio implementado
1. `scripts/live-hero-audit.mjs` ahora:
   - cache-bustea `engine-ab.js`, `engine-ac.js`, `engine-ah.js`, `hero.PNG` y `armor-aura.js`;
   - espera explícitamente `MOV-plant-audit-v1`;
   - deriva `plantFrame`/`plantPhase` del runtime en lugar de hardcodear frame 0;
   - valida release estable con `visualFrame === plantFrame`, `stridePhase === plantPhase`, `strideDistancePx === 0`;
   - mide RIGHT -> LEFT reversal -> release -> diagonal -> release;
   - exige reversal observado, 0 accidental-idle, 0 frame-jump y >=2 releases;
   - conserva invariantes de escala 1.15x, collider, footRoot, preprocess del sprite y aura ligada a presentación.
2. Se añadió `.github/workflows/hero-live-audit.yml` para ejecutar el audit en LIVE Pages en móvil 390x844 DPR2 y desktop 1280x720 DPR1, esperando antes que Pages publique la revisión del auditor y subiendo screenshots + JSON.

### Experimento / métricas
Misma traza en ambos viewports:
- RIGHT displacement > 8 px
- LEFT reversal displacement > 8 px
- diagonal con ambos ejes > 4 px
- reversalCountDelta >= 1
- reversalAccidentalIdleDelta = 0
- reversalFrameJumpDelta = 0
- releaseCountDelta >= 2
- release visualFrame == runtime plantFrame
- release stridePhase == runtime plantPhase +/- 0.001
- release strideDistancePx == 0
- visualScale = 1.15
- colliderRadius == player.radius
- footRootX == physicsRootX; footRootY - physicsRootY == 10
- 0 console/page errors, 0 failed requests, 0 HTTP >= 400

### Riesgos
- El workflow nuevo necesita confirmación LIVE; mientras no termine verde, no debe declararse validado.
- El gate de publicación identifica la revisión por marcadores del script, no por hash criptográfico del asset servido.
- La ronda no cambia gameplay ni escala; solo restaura la fidelidad del instrumento de medición.
