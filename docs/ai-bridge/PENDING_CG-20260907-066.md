## PROBLEM
The LIVE hero renderer currently uses authored row 2 for both RIGHT and LEFT, producing LEFT by mirroring row 2 around actor.x. However, the later-loaded character appearance module declares the same assets/hero.PNG as a 4-row directional sheet with separate LEFT=row 1 and RIGHT=row 2, mirrorFaces=false, plus per-frame foot/body metrics for both rows. The hero audit already computes row1-vs-row2 and row1-vs-mirrored-row2 RGBA similarity, but the renderer never uses those measurements to decide whether the native LEFT row is preferable. If row 1 contains meaningful authored left-facing asymmetry, continuing to mirror row 2 can throw away intentional silhouette, arm swing, garment/accessory asymmetry, and foot-contact information exactly in the lateral motion path the user wants to improve.

## EXTERNAL_EVIDENCE
- Godot official 2D tutorial explicitly demonstrates mirroring one authored right-facing walk for left movement with AnimatedSprite2D.flip_h; this confirms mirroring is a valid low-cost technique when the art is designed for it: https://docs.godotengine.org/en/latest/getting_started/first_2d_game/03.coding_the_player.html
- Godot AnimatedSprite2D also supports distinct animation/frame resources and independent flip_h/flip_v state; using authored directional rows is equally native when the sheet provides them: https://docs.godotengine.org/en/4.6/classes/class_animatedsprite2d.html
- Unity SpriteRenderer.flipX documents that flipping is a render-only operation, so testing native LEFT versus mirrored RIGHT can remain presentation-only without touching colliders/gameplay: https://docs.unity3d.com/cn/6000.0/ScriptReference/SpriteRenderer-flipX.html
- Community counterevidence: IndieDev discussion reports mirrored left/right as normal for assets authored in only one side direction. Therefore native LEFT should not be enabled merely because row 1 exists; it must beat the mirrored row in measured silhouette/contact/quality: https://www.reddit.com/r/IndieDev/comments/1ijf1cl
