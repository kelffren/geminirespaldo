# CG-20260910-041 — PvP camera dead-zone screen-space parity

STATUS: VERIFIED
DATE: 2026-09-10
AREA: PvP / Camera / movement feel
OWNER: KeloCamera (`src/core/camera-system.js`)

## Problem
The legacy follow math in `engine-a.js` computed `deadW = screenW * CONFIG.deadXRatio` and compared that value against a world-space player/camera delta. Under effective zoom below 1, especially mobile landscape, the intended screen-space dead-zone collapsed and the camera chased lateral movement too early.

## Baseline evidence
Chromium PvP reproduction using the LIVE runtime:
- mobile landscape 844x390 DPR2: semantic dead-zone 84.4 CSS px, legacy projected dead-zone 43.210227 px.
- desktop 1440x900: semantic dead-zone 144 CSS px, legacy projected dead-zone 130.5 px.
- no page errors in the valid baseline run.
- first harness attempt was invalid because it assumed lexical legacy globals were `window` properties; the harness was corrected and rerun before implementation.

## Candidate A
Commit `4f55fc54a8dfb9df2fc852a7329e9b8851325516`.
KeloCamera remains the sole owner. `getFollowTuning()` retains semantic screen-space ratios, while the transitional legacy CONFIG getters for `deadXRatio/deadYRatio` expose `semanticRatio / effectiveZoom` to `engine-a`, whose delta comparison is world-space. Damping, look-ahead distance/decay, input, player simulation, combat and networking were not changed.

## Runtime result
Camera Foundation CI candidate run `34472835481`: SUCCESS.
Chromium winner reproduction:
- mobile landscape: semantic 84.4 px, projected legacy 84.4 px; onset about 0.70–0.75 s depending browser cadence; no page errors.
- desktop: semantic 144 px, projected legacy 144 px; onset about 0.69 s; no page errors.

## Deterministic 60/90/120 evidence
Added `scripts/audit-pvp-camera-follow-timing.mjs` and gated it in Camera Foundation CI.
At 60/90/120 Hz the winner preserves exact screen-space dead-zone parity:
- mobile landscape: 84.4 px at all three rates (baseline 43.210227 px).
- desktop: 144 px at all three rates (baseline 130.5 px).
Winner onset remains refresh-rate consistent in the deterministic trace.

## Refinement / winner lock
- `scripts/camera-system-contract-audit.js` locks semantic/legacy unit parity.
- `scripts/live-pvp-camera-follow-judge.mjs` is now a hard browser winner gate: mobile landscape and desktop must have a real follow onset, no page errors, screen-deadzone camera version, and projected dead-zone within 0.25 px of semantic target.
- `scripts/audit-pvp-camera-follow-timing.mjs` locks 60/90/120 Hz behavior.

## Agent B verdict
GANA.
Primary perceptual improvement: lateral PvP framing now preserves the intended amount of screen freedom before follow begins instead of becoming much tighter simply because landscape zoom changed. This improves strafe/reversal readability and reduces premature camera chasing without changing gameplay movement or server semantics.
