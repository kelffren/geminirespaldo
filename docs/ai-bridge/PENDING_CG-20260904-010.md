### PROBLEM
The local hero stride phase is correctly driven by actual world distance, but `engine-ac.js` converts that continuous phase to `frame = floor(stridePhase * 4) % 4`. Therefore every source column receives exactly one quarter of the gait cycle. The current repository does not document that the four authored hero columns are intended to represent equally spaced temporal poses. If the atlas contains contact/down/passing/up-like poses with different perceptual importance, equal 25% buckets can create a robotic cadence, weak foot planting, or visible pops even when world-distance synchronization is mathematically correct.

### CONFIRMED_IN_GEMINI
- Current `main` `engine-ac.js` defines a distance-driven stride phase and maps it to exactly four equal phase intervals with `Math.floor(v.stridePhase * 4) % 4`.
- `engine-ab.js` consumes `m.frame` directly as the source-sheet column. There is no per-frame duration table, contact-marker metadata, gait-specific column sequence, or pose semantic map.
- WALK and RUN reuse the same four columns; only cycle world distance changes (50 px walk, 90 px run). Therefore authored pose timing cannot currently differ between walk and run.
- No repository search result was found that documents `hero.PNG` columns as a contact/passing/up/down contract. This absence is not proof of incorrect art; it means the runtime currently has no explicit timing contract to validate against.

### EXTERNAL_EVIDENCE
- Animation practice commonly treats contact/down/passing/up as semantically distinct gait poses rather than arbitrary equal-value pictures; community animation references emphasize contact and passing as primary keys and note that bad timing around foot contact causes loss of weight/foot sliding.
- A recent pixel-art animation policy on GitHub explicitly orders gait poses as contact, down, passing, up and opposite-side equivalents, reinforcing that pose semantics can be encoded independently from uniform playback.
- Godot issue #79244 documents a real animation-loop defect where an unexpected frame at the loop boundary visibly corrupted an otherwise correct directional sprite cycle, showing that discrete frame sequence/timing errors can remain visible even when direction selection is correct.
- Counterevidence: many successful four-frame pixel-art walks do use even timing. Equal 25% timing is therefore a valid baseline and must not be changed unless the real `hero.PNG` pose semantics and A/B measurements justify it.

### HYPOTHESIS
The current lateral movement may feel more mechanical than necessary because phase-to-frame quantization assumes all four authored poses should occupy identical spatial/time fractions. A tiny pose-aware phase map, or an authored replacement atlas with deliberate equal spacing, could improve planting and premium cadence without changing physics. However, if the existing four columns were authored specifically for equal spacing, the baseline should remain unchanged.

### PROPOSED_CHANGE
Do not modify production yet. First classify all four lateral `hero.PNG` columns by visual semantics and foot position. Then compare:
A) BASELINE_EQUAL: current 0.00-0.25-0.50-0.75 boundaries.
B) POSE_AWARE_PHASE_MAP: same four source columns, but configurable normalized phase boundaries chosen from measured foot-contact continuity; no change to world movement, cycle distance, collider or camera.
C) SEQUENCE_ONLY: test alternate legal column ordering if visual classification proves the current sheet order is not a true gait order.
D) AUTHORED_EQUAL: if procedural timing cannot fix foot continuity, keep runtime equal timing and change the atlas offline instead; benchmark only after a visual-art candidate exists.
Keep walk and run independent in the experiment; do not assume one timing map fits both.

### EXPERIMENT
1. Capture the four lateral source columns at native crop and label visible left/right foot positions, support foot, body height, arm phase and apparent contact state.
2. With camera fixed and open terrain, replay identical RIGHT and LEFT traces at stable walk and stable run.
3. Instrument `stridePhase`, selected frame, frame-entry phase, world distance since prior frame change, and projected planted-foot position.
4. Test A baseline first at 60/90/120 Hz. Confirm same world trace and same phase boundaries across refresh rates.
5. If asset classification shows unequal semantic spacing, test 2-3 conservative B maps. Example search space only: move each internal boundary by at most ±0.05 phase while preserving cyclic order. Do not choose values by intuition; derive candidates from planted-foot continuity and visual review.
6. If frame order itself appears inconsistent, test C without altering durations.
7. Repeat the winning candidate across 1.00x visual scale; only after a winner, validate at 1.15x and 1.25x because timing defects become more visible when the avatar is larger.
8. Use the exact same movement/camera trace for every candidate and re-measure.

### RISKS

- A timing map cannot repair fundamentally poor frame art; authored replacement may be the correct endpoint.
