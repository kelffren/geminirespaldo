### PROBLEM
Kelo World needs a separate PvP mode/world that exposes the existing 5-slot ability bar, supports mobile tap targeting/basic attacks and can later migrate from local authority to server authority without rebuilding movement, rendering or ability data. The social world must remain non-combat.

### CONFIRMED_IN_GEMINI
Current `main` already has: core input/movement/physics/camera in `engine-a.js`; social routing/quick travel in `engine-c.js`; new data-driven abilities in `src/abilities/*`; a 5-slot loadout; local ability cooldowns and FX; an old `arenaPvP`/simulated-player path; optional networking in `engine-net.js`; and a server `combat:resolve` endpoint that currently resolves Nobleza-adjusted base damage but is not a complete authoritative PvP simulation. `index.html` hides the action bar in `body.social-mode`.

### EXTERNAL_EVIDENCE
No external architectural claim is required for this first implementation: the key design choice follows the repository's own existing client/server split. The later networking phase should still benchmark touch latency, prediction and reconciliation before adding competitive multiplayer.

### HYPOTHESIS
A low-risk vertical slice can reuse the current Ability Engine and an existing simulated-player entity while adding a separate PvP world-mode owner that handles combat permission, command/result boundaries and presentation. This avoids duplicating movement or ability systems and preserves a migration path where only combat execution authority moves to the server.

### PROPOSED_CHANGE
Implemented first slice on `main`: add `src/systems/pvp-world.js`; add a `PVP` menu-footer button; load the PvP owner before the Ability Engine so its arena/world presentation sits below ability VFX; reuse one simulated player as a dummy; expose `SELECT_TARGET`, `BASIC_ATTACK`, `CAST_ABILITY` commands through a local authority; tap enemy for basic attack; tap skill then enemy/ground for ability requests; show/hide the existing action bar by entering/leaving social-mode; restore social player/dummy state on exit. Document the migration boundary in `docs/PVP_WORLD_V1.md`.

### DO_NOT_ASSUME
Do not call this server-authoritative. Do not assume direct calls to `KeloAbilities.engine.cast()` are yet world-permission-gated: that Ability Engine predates the new PvP world. UI/input is separated, but internal validation still needs a combat-permission guard before competitive multiplayer. Do not assume the current server `combat:resolve` validates target, range, cooldown, projectile collision or death.

### RISKS
The current Ability Engine can still be invoked programmatically outside PvP because `validateCast()` does not yet consume the world permission. The PvP presentation currently reuses a coordinate-space arena overlay rather than a separately streamed server room/map asset. Existing social simulated-player data is temporarily reused and restored. Touch conflict between left joystick and combat tap still requires real mobile audit.
