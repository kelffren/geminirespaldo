## CG-20260914-001 — Mobile AI execution workflow is now canonical

### Qué cambió
Se creó `AI_MOBILE_EXECUTION_BRIDGE.md` en la raíz de `kelffren/gemini` y se registró como documentación canónica.

### Regla operativa
Kelo dirige Kelo World desde iPhone. El flujo principal no debe depender de una computadora personal encendida o disponible.

### Arquitectura

```text
Kelo iPhone
→ IA/agente
→ GitHub main
→ GitHub Pages LIVE
→ TinyFish para interacción/QA remota
→ evidencia
→ fix/commit
→ repetir prueba atómica
```

AppDeploy queda como apoyo para probes, builds, screenshots QA y errores runtime; no se debe confundir una captura/carga correcta con gameplay validado.

### Regla TinyFish
Usar una sola meta principal por run. No mezclar movimiento + menús + editor + mapa + diagnóstico completo en una misión larga. Secuencia recomendada para el freeze actual:

1. BOOT
2. MOVEMENT
3. OPEN EDITOR
4. PRE-MAP
5. MAP START
6. FREEZE BOUNDARY
7. POST-FIX

Estados válidos: `CONFIRMED PASS`, `CONFIRMED FAIL`, `INCONCLUSIVE`, `BLOCKED`, `NOT TESTED`.

### Fuente completa
Leer antes de continuar trabajo remoto/móvil:

`AI_MOBILE_EXECUTION_BRIDGE.md`

No sustituye `AGENTS.md`, Foundation, ONLINE-FIRST, Bug Intelligence ni las gates existentes. Si una gate requerida no puede ejecutarse, declararlo; no inventar PASS.
