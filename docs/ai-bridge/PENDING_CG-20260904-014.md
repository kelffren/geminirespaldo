### PROBLEM
Current `main` has just formalized and LIVE-validated a `drawPostActors()` environment contract. `engine-c.js` renders all actors (including the `engine-ab.js` hero nameplate) and then calls `KELO_WORLD_RENDERER.drawPostActors(ctx)`. `environment-layer-stack.js` defines both `props_front` and `vfx_weather_lighting` as post-actor phases. `plaza-nature.js` now places tree/front-prop occlusion in `props_front`, but its candidate overlap and clip geometry are derived from `actor.radius` and `actor.y`, not from the production hero's visual body bounds / `footY`. This creates a new scaling-specific risk: a 1.15x/1.25x body can outgrow the collider-derived occlusion clip, while the nameplate currently has no explicit independent occlusion policy. A future CG-012 visual-bounds fix could unintentionally start covering nameplates that currently remain visible largely because the clip does not extend high enough.

### CONFIRMED_IN_GEMINI
- Current baseline `main` is `6a762886224b46468203f0971dc812dc1d836895`; `index.html` declares Kelo World V6.23.
- `engine-c.js::render()` executes world/pre-actor draw, actors (`renderAvatar` for simulated players and local player), then `KELO_WORLD_RENDERER.drawPostActors(ctx)`. Therefore any `props_front` layer is above the actor render output.
- `environment-layer-stack.js` explicitly declares `POST_ACTOR_PHASES = new Set(['props_front','vfx_weather_lighting'])` and dispatches them only through `drawPostActors()`.
- Recent validated commits preserved this post-actor contract through Plaza and architecture renderer proxies. `docs/VISUAL_DIRECTION_MEMORY.md` now records the contract as validated at 390x844 CSS / 780x1688 physical.
- `engine-ab.js` production path draws the hero PNG and then immediately draws the actor nameplate in the same `renderAvatar()` call. It has no separate body/label pass. Current visual foot anchor is `footY=p.y+10`; body draw height is derived from the spritesheet via `dh=Math.round(54*(FH/FW))`.
- `plaza-nature.js::overlapActor()` uses only `actor.x/y` plus `actor.radius` to select prop/actor intersections.
- `plaza-nature.js::drawFrontOcclusion()` uses `r=Math.max(22,(actor.radius||20)+8)` and clips the redrawn front prop to `rect(actor.x-r, actor.y-r*1.8, r*2, r*2.5)`. With the normal radius 20 this resolves to r=28 and a clip extending from roughly `actor.y-50.4` to `actor.y+19.6`, independent of the PNG's actual visual height and independent of future presentationScale.
- Because the nameplate is drawn as part of `renderAvatar()` before `drawPostActors()`, it is technically below post-actor props. However its current anchor is above the body (`footY-dh-6`) and the collider-derived tree clip may not reach it. Thus current nameplate readability is not governed by an explicit policy; it can be an accidental consequence of undersized occlusion clips.
- Binary connector inspection still cannot expose `hero.PNG` natural dimensions directly, so exact production `dh` is not claimed here. The architectural mismatch does not depend on knowing that number: the front clip is radius-derived while body height is spritesheet/presentation-derived.
- Redundancy/responsibility scan: actor body + nameplate are coupled in `engine-ab.js`; post-actor body occlusion lives in environment modules; selection/clip logic is duplicated conceptually with other depth systems. Do not refactor these together until measurements show the minimum contract needed.

### EXTERNAL_EVIDENCE
- Godot's official CanvasLayer documentation separates rendering layers/transforms and notes that UI/HUD commonly belongs on an independent layer, while ordinary 2D draw order can be controlled separately. This supports making label/nameplate policy explicit rather than letting world foreground occlusion accidentally decide it.
- A real DelvUI GitHub bug (#1123) documents NPC nameplates disappearing when occlusion mode is enabled even though the nameplate itself is enabled. This is concrete evidence that coupling world occlusion and label visibility can create user-facing readability regressions.
- Bevy issue #1275 discusses the need for ergonomic semantic 2D layers such as units vs in-game UI rather than scattered/manual z-order values. This supports named presentation passes over ad-hoc clipping behavior.
- Counterevidence: nameplates do not always need to be globally above the world. In immersive/social scenes, allowing some environmental occlusion can reduce UI clutter and preserve depth. Therefore the proposal is NOT “always draw every name above everything”; it is to define and benchmark a deliberate policy.
- Counterevidence: broad visual-body clips can increase overdraw and can make large trees/foregrounds cover too much of a scaled actor. Accurate visual bounds must be clamped/cheap and should not become physics bounds.

### HYPOTHESIS
For larger characters, Kelo World needs three explicit presentation contracts: `visualBodyBounds` for foreground intersection, `depthRoot/footRoot` for Y-order decisions, and `labelAnchor + labelOcclusionPolicy` for nameplates. Keeping collision radius unchanged while deriving front-prop clips from visual body bounds should remove head/shoulder leak-through at 1.15x/1.25x. Separating the label pass from the body pass should prevent that correction from unexpectedly hiding names. The winning label policy may be always-readable, softly occluded/faded, or depth-aware; benchmark rather than assume.

### PROPOSED_CHANGE
Do not refactor production immediately. Instrument and compare in stages:

A. `BASELINE_COLLIDER_CLIP`: current radius-derived candidate + clip, current nameplate coupled to actor draw.
B. `VISUAL_BODY_CLIP_PROBE`: compute visual body AABB/footRoot from the production renderer and use it only for front-prop clip diagnostics; do not change pixels yet. Count cases where visual body intersects a foreground prop but collider-derived clip/candidate misses it.
C. `VISUAL_BODY_CLIP_BODY_ONLY`: front props may occlude the measured body extent, but nameplate is redrawn in a separate label pass after `drawPostActors()` so body-depth correction cannot silently change label readability.
D. `LABEL_POLICY_AB`: with C fixed, compare (D1) label always above world foreground, (D2) label fades when its actor is strongly occluded, (D3) label follows actor/world occlusion. Preserve the same label anchor and text metrics so only visibility policy changes.

Keep collision radius, physics, network state, movement, gait and camera unchanged. Do not use DOM overlays for world-following labels in this first experiment; Canvas2D screen/world coordinate consistency should be measured first.

### DO_NOT_ASSUME
- Do not assume `actor.radius` should grow when the sprite grows.
- Do not assume the current tree clip is visibly wrong at 1.00x; measure crossings.
- Do not assume nameplates must always be visible. The user priority includes legibility, but visual depth also matters.
- Do not allow `visualBodyBounds` to become collision bounds.
- Do not use one generic full-sprite AABB as Y-sort/depthRoot; body intersection and depth ordering are separate responsibilities.
- Do not fix Plaza nature and then blindly copy the same geometry into fountain/Gardens; replay the same metric contract per compositor.
- Do not merge body, shadow and label passes into one new abstraction until CG-012/013 establish their actual roots/order.

### RISKS
- Expanding clips from collider-sized to full visual bounds increases redraw area/overdraw, especially with 25–50 actors.
- Redrawing labels after every post-actor layer without a dedicated pass could duplicate text, Aura overlays or other actor decorations.
- `vfx_weather_lighting` is also a post-actor phase; a universal “labels last” rule may cause names to ignore atmospheric effects that should legitimately affect the scene. If needed, labels should sit after `props_front` but before selected full-screen/weather UI effects rather than simply last.
- Large avatars make overlap conflicts more frequent, so label-label collisions may become a separate problem; do not solve that inside this occlusion patch.
- If exact visual bounds require reading alpha pixels every frame, reject that design. Bounds should be static/authored per pose/scale or cheaply derived from renderer metadata.
