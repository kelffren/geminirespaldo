### PROBLEM
Kelo now has a semantic avatar presentation contract with footRoot, visualHeight and nameplateAnchor, but the modern `KeloActorNameplate` still positions identity text from `actor.y - actor.radius - 19`. That couples a visual/UI question to the gameplay collider and does not follow avatar scale. At the same time the LIVE Character Appearance renderer still paints a simple actor name itself, then the higher-priority Actor Nameplate middleware calls `next()` and paints the modern name/nobility/title again. This means the current custom hero path has two independent name painters and the modern one is anchored far inside the semantic visual envelope. Increasing avatar scale from 1.15x to 1.20x makes the mismatch larger while correctly leaving collision unchanged.

### CONFIRMED_IN_GEMINI
- Current live baseline for this research is main `421248faf3edd2bddc448ea06fe69004dc6e6674` after the bridge bot restored the append-only history.
- `index.html` declares V6.54 and loads `engine-ab.js`, `src/characters/character-appearance.js`, then later `src/ui/player-nameplate.js`; all are LIVE.
- `engine-ab.js` publishes `KELO_AVATAR_PRESENTATION` with `footRootY = actor.y + 10`, `visualHeight = round(81 * 1.15) = 93`, `visualTop = footRootY - visualHeight`, and `nameplateAnchorY = footRootY - visualHeight - 6`. At 1.15x this semantic nameplate anchor is `actor.y - 89` while the visual top is `actor.y - 83`.
- `player-nameplate.js::draw()` ignores that contract. With the default player radius 20 it uses `baseY = actor.y - 20 - 19 = actor.y - 39`. With only the name line, the modern name is therefore 50 world px lower than the semantic `nameplateAnchorY` and 44 px below the semantic visual top. With nobility/name/title, the three modern lines occupy roughly actor.y-65, actor.y-52 and actor.y-39; all remain inside the 93px semantic vertical envelope rather than above it.
- At a presentation-only 1.20x candidate, visualHeight becomes `round(81 * 1.20) = 97`, visualTop becomes actor.y-87 and semantic nameplateAnchor becomes actor.y-93, while the collider-derived modern name remains actor.y-39. The anchor mismatch therefore grows from 50px to 54px despite unchanged physics.
- `character-appearance.js::renderAppearance()` separately calls `ctx.fillText(actor.name || 'Kelo', layout.nameplateAnchorX, layout.nameplateAnchorY)` after drawing the custom sprite.
- `KeloActorNameplate` is middleware priority 500 and explicitly calls `next()` before `draw(actor)`. Character Appearance is middleware priority 200 and handles the custom hero without calling its own `next()`. Therefore the full LIVE custom-hero chain paints the Appearance simple name first and then the modern Actor Nameplate text: the duplication is architectural, not merely two dormant code paths.
- `KeloAvatar` is the correct composition owner and already defines priority-desc middleware; no new nameplate manager or avatar wrapper is warranted.
- `imageSmoothingEnabled=false` remains active in Character Appearance. The 256x384 source frame is still being downscaled at 1.15x/1.20x rather than enlarged beyond native source resolution, so this particular nameplate defect is independent of sprite source resolution.

### EXTERNAL_EVIDENCE
- MDN documents `CanvasRenderingContext2D.imageSmoothingEnabled=false` as the standard Canvas 2D control to retain hard pixel edges when scaled; Kelo already uses this, so a nameplate-anchor fix does not require changing sprite filtering. https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/imageSmoothingEnabled
- Godot's CanvasLayer documentation distinguishes world rendering from UI layers with independent transforms. This supports keeping UI ownership conceptually separate from physics/collider geometry, but does not imply Kelo must move nameplates to screen-space in this pass. https://docs.godotengine.org/en/stable/tutorials/2d/canvas_layers.html
- Community practice for floating UI commonly anchors the UI to an explicit point on the actor and, when desired, projects that point to screen space. A 2025 r/gamedev discussion describes this world-anchor→screen-position pattern and warns that world-space UI can inherit camera zoom/blur characteristics. This is useful implementation context, not authoritative evidence that Kelo should switch rendering spaces now. https://www.reddit.com/r/gamedev/comments/1m57l5m/
- Counterevidence: world-space nameplates are also a normal technique. The issue here is not world-space versus screen-space by itself; it is that Kelo's modern nameplate uses collider radius while the avatar owner already publishes a semantic visual/nameplate anchor.

### HYPOTHESIS
Before any 1.15x→1.20x scale experiment, consolidate identity text ownership and make the modern nameplate consume the existing semantic avatar presentation anchor. This should eliminate duplicate names and keep name/nobility/title above the visible character automatically as visual scale changes, while collider radius, world movement, collision and camera stay identical. The smallest correct change is presentation-only: Actor Nameplate becomes the sole identity text painter; Character Appearance stops painting its legacy/simple name when the modern nameplate owner is available; Actor Nameplate uses `KELO_AVATAR_PRESENTATION.get(...)` nameplateAnchorX/Y with its current collider formula only as a legacy fallback.

### PROPOSED_CHANGE
1. Extend `KeloActorNameplate.draw/resolve` to obtain the existing presentation snapshot/anchor when available. Do not infer head position from `actor.radius` on modern actors.
2. Stack nobility/name/title upward/downward from the semantic nameplate anchor according to one documented convention, keeping all lines outside the semantic visualTop plus a small gap. Preserve current fonts/colors unless measurement shows readability issues.
3. Remove the simple `actor.name` paint from Character Appearance once the modern nameplate owner is confirmed LIVE in the same test, or gate it strictly as a fallback when `KeloActorNameplate` is unavailable. Do not create a second text layer.
4. Add/extend one audit around the actual KeloAvatar middleware chain. Assert exactly one modern name paint for a custom hero, semantic anchor use, and collider independence.
5. Only after the 1.15x baseline passes, repeat the same trace at 1.20x. Scaling must move the nameplate with visual bounds while `actor.radius` and collision traces remain unchanged.

### DO_NOT_ASSUME
- Do not enlarge `actor.radius` to make the nameplate move; collider is gameplay, not silhouette/head geometry.
- Do not move all nameplates to DOM/screen-space in this pass; that is a separate readability/performance choice.
- Do not change camera zoom, DPR policy, font size, sprite smoothing, body scale and nameplate ownership simultaneously.
- Do not remove the Character Appearance fallback label unless the modern owner is proven present for the same actor/render path.
- Do not treat semantic `visualTop` as a depth-order key; `depthRoot`/footRoot remains the depth contract.
- Do not claim that 1.20x sprite quality is validated from math alone; browser/mobile screenshots are still required.

### RISKS
Removing the Appearance label without verifying Actor Nameplate availability could temporarily hide names during partial/dormant render paths. A three-line nameplate can still collide with other actors or top-screen edges even when correctly anchored; collision/decluttering is a later UI problem. World-space text may scale with camera zoom and can become small/large across viewport policies; do not solve that by coupling back to collider. Larger characters can increase visual crowding even after anchor correctness, so 1.20x still needs mobile screenshot/FPS gates.
