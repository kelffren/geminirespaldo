### PROBLEM
The current movement state and the actual rendered sprite column disagree when the player stops. `engine-ac.js` deliberately settles release to `PLANT_FRAME` (default 2) and publishes `visualFrame=2`, but the live hero renderer in `engine-ab.js` executes `if (!m.on) return 0` before consulting `m.frame`. Therefore an idle/released player is rendered from column 0 even though the movement audit reports the authored plant frame 2. The current Playwright audit validates only the movement state (`visualFrame === plantFrame`) and not the column actually sampled by `drawImage`, so it can report a successful planted release while the pixels do something different.

### CONFIRMED_IN_GEMINI
1. Current `main` at the start of this round: `b3bf2765eefe45ae7ad2e6d1efd6ecc9aa2b41be` (`chore: remove temporary katana live audit workflow`).
2. `index.html` is currently V6.33 and loads `engine-ab.js?v=240`, then `character-appearance.js?v=2`, then `engine-ac.js?v=222`. `ENGINE_MAP.md` is older (audited V6.16), so LIVE load order/code is authoritative.
3. `engine-ac.js` defines `DEFAULT_PLANT_FRAME = 2`, `PLANT_PHASE = PLANT_FRAME / 4`, and when visual movement becomes off it sets `v.stridePhase = PLANT_PHASE`, `v.frame = PLANT_FRAME`. `publishAudit()` exposes those as `plantFrame`, `visualFrame`, and `stridePhase`.
4. `engine-ab.js::motionOf()` correctly carries `_visualMotion.frame` into `m.frame`, but `stepCol(p,m)` starts with `if (!m.on) return 0;` and only checks `m.frame` after that. Thus the stopped state forcibly renders column 0.
5. `scripts/live-hero-audit.mjs::assertPlantedRelease()` checks `movement.visualOn === false`, `movement.visualFrame === movement.plantFrame`, phase, and stride distance, but does not observe the renderer-selected sprite column or rendered pixels. Therefore the existing test proves state convergence, not presentation convergence.
6. `src/characters/character-appearance.js::frameColumn()` repeats the same policy for non-delegated appearances: `if (!motion.moving) return 0;` before consulting `motion.frame`. The current player and retired crimson bot delegate to the legacy hero, but this duplicated rule would reintroduce the same bug during a future shared-renderer migration unless the contract is fixed centrally.
7. No new relevant Grok response exists after `GC-20260831-003`; therefore there is no implementation feedback invalidating this observation.

### EXTERNAL_EVIDENCE
- Godot's animation APIs expose and honor an explicit current frame as presentation state. Its AnimatedTexture documentation states that `current_frame` is the currently visible frame, reinforcing the expected contract that a selected animation frame should determine what is shown rather than be silently replaced by another idle column: https://docs.godotengine.org/en/stable/classes/class_animatedtexture.html
- A Godot regression report demonstrates the broader class of problem where another animation/reset layer overriding the `frame` property causes the visible animation to disagree with intended state; the important lesson for Kelo is to verify which layer has final ownership of the rendered frame: https://github.com/godotengine/godot/issues/89163
- A second historical Godot issue shows how another sprite presentation setting (`Region`) can override the configured animation frame, creating the impression that the frame system is broken. This is analogous to Kelo's renderer-level `return 0` overriding the gait-selected plant frame: https://github.com/godotengine/godot/issues/16007
- Playwright officially supports screenshot visual comparisons (`toHaveScreenshot`) and pixel-difference thresholds. Kelo should use rendered evidence for this contract instead of validating only JavaScript state: https://playwright.dev/docs/test-snapshots
- Community evidence around top-down walk cycles notes that abrupt idle/walk switching and resetting to a fixed frame can make transitions feel visibly wrong; this is not proof of Kelo's artistic best frame, but it supports benchmarking the visible release rather than assuming state counters are sufficient: https://www.reddit.com/r/godot/comments/1dhb02v/ and https://www.reddit.com/r/gamemaker/comments/1n07t5i/

### HYPOTHESIS
The current release/plant improvement is not fully reaching the screen. A meaningful portion of the remaining 'unplanted' lateral feel after release can come from the renderer forcing column 0 at `m.on=false`, while the movement layer believes it has settled to authored column 2. If the renderer is changed to honor the explicit `_visualMotion.frame` even when movement is off, the visible release should match the plant-frame contract with zero physics/camera/collider change.

A secondary architectural hypothesis is that 'moving vs idle' should choose which animation state is active, but should not silently discard an explicit frame supplied by the authoritative presentation state. The same precedence rule should be shared by the legacy hero and future appearance renderer.

### PROPOSED_CHANGE
Do NOT refactor the animation system first. Instrument the final rendered column, establish baseline, then make the smallest candidate change.

Candidate A in `engine-ab.js::stepCol()`:
- if an explicit finite `m.frame` exists, return that frame modulo `COLS` regardless of `m.on`;
- only fall back to idle column 0 when no explicit visual frame exists and `m.on` is false;
- preserve wall-clock fallback behavior only for actors without `_visualMotion`.

Conceptual precedence:
`explicit presentation frame -> movement fallback animation -> default idle frame`.

Apply the equivalent precedence to `character-appearance.js::frameColumn()` only after the legacy-hero A/B proves the contract, so shared-renderer migration cannot revive the same bug.

Extend the audit with a renderer-facing metric such as `KELO_HERO_RENDER_AUDIT.lastColumn`, updated immediately before `drawImage`. Do not infer the visible frame from `KELO_MOVEMENT_AUDIT`.

### DO_NOT_ASSUME
- Do not assume frame 2 is artistically superior merely because `engine-ac.js` calls it `PLANT_FRAME`. First capture frame-0-vs-frame-2 release screenshots and inspect foot/support silhouette.
- Do not change movement physics, stop latency, stride phase, footRoot, camera, collider, zoom, crop, scale, or sprite filtering in the same experiment.
- Do not claim the existing `assertPlantedRelease()` proves visible planting; it proves only gait-state values.
- Do not remove the legacy idle fallback for actors that have no `_visualMotion` until their behavior is independently measured.
- Do not migrate the player to `character-appearance.js` as part of this fix.
