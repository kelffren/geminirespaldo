### PROBLEM
The live movement core had a continuous physical speed curve but a discontinuous visual stride-length rule at `GAIT_RUN_START = 0.70`: WALK used 50 world px per four-frame cycle and RUN immediately used 90. Around the threshold this made physical speed almost unchanged while visual cycle frequency dropped by roughly 44%, which can make Kelo appear to accelerate while his legs slow down.

### CONFIRMED_IN_GEMINI
- Current `engine-ac.js` before this change used `GAIT_RUN_START = 0.70`, `WALK_CYCLE_WORLD_PX = 50`, `RUN_CYCLE_WORLD_PX = 90`.
- `speedFor(mag)` is continuous and `updateMovement()` is DIRECT, so this discontinuity was visual cadence, not a physics acceleration jump.
- Stride phase already advances from actual world distance, which is desirable and must be preserved.
- Local collider remains `localPlayer.radius = 20` in `engine-a.js` and this implementation does not change it.
- `engine-ab.js` reads `_visualMotion.frame`, so the change can remain isolated in gait/stride ownership (`engine-ac.js`).
- `engine-ah.js` only applies hard-stop after movement and does not need modification for this experiment.

### EXTERNAL_EVIDENCE
Prior cumulative research (CG-20260904-020) contrasted engine practice and community evidence that animation cadence should stay coherent with world travel to avoid skating/foot sliding, while also preserving the counterpoint that a true RUN may legitimately have a longer stride than WALK. Therefore the target is not equal cycle distance; it is removal of the abrupt threshold discontinuity while preserving a longer run stride at full input.

### HYPOTHESIS
Interpolating cycle distance continuously from 50 world px at the RUN threshold to 90 world px at full input will remove the ~44% cadence cliff without changing physics, collisions, max speed, camera, direction, or stride phase. The current four-frame art remains unchanged.

### PROPOSED_CHANGE
Implemented as an isolated experiment:
1. Add `cycleWorldPxFor(mag, gait)` in `engine-ac.js`.
2. WALK remains exactly 50 world px/cycle.
3. At RUN threshold (0.70), RUN starts at 50 world px/cycle and linearly grows to 90 at magnitude 1.0.
4. Preserve existing `stridePhase`; never reset phase on WALK↔RUN.
5. Add narrow rollback flag: default V2 behavior; `?movCadenceV2=0` restores the old hard 50→90 switch.
6. Expose `cadenceV2` and `cycleWorldPx` through `window.KELO_MOVEMENT_AUDIT`.
7. Bump only the `engine-ac.js` cache key in `index.html` so Pages can load the experiment.
