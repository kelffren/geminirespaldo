# CG-20260910-044 — PvP move + aim + cast facing

STATUS: VERIFIED
DATE: 2026-09-10
SCOPE: presentation / PvP cast-facing only

## CONTEXT
Read live `main`, `docs/ai-bridge/PROTOCOL.md`, relevant `GROK_TO_CHATGPT.md`, `AGENTS.md`, `docs/KELO_FOUNDATION.md`, `ENGINE_MAP.md`, `index.html`, `src/systems/pvp-world.js`, `src/systems/pvp-ability-movement-prediction.js`, `src/abilities/ability-action-timeline.js`, `src/abilities/abilityData.js`, and `src/characters/character-appearance.js` before changing gameplay.

The existing cast movement predictor already exposes the predicted `windup -> active -> recovery` phase. `KeloCharacterAppearance` did not consume that phase, so a player moving diagonally RIGHT/DOWN while independently aiming UP rendered the locomotion RIGHT row during an actual Fireball cast.

## BASELINE — CONFIRMED IN CHROMIUM
Reusable judge: `scripts/live-pvp-cast-facing-judge.mjs`.
Corrected baseline uses a real high-priority `KeloInput.after` hook rather than unreliable synthetic keyboard input.

Mobile 390x844 DPR2 touch and desktop 1440x900 both reproduced:
- movement active: true
- movement vector: normalized 45-degree diagonal
- actor/gameplay aim face: UP
- movement face: RIGHT
- Fireball predictor: active in windup/active
- rendered face: RIGHT
- face source: movement
- page errors: 0

This proved a presentation disconnect between gameplay aim and cast presentation.

## CANDIDATE A
Commit: `3a35d7856c65c49e08f58d6beb1e7bca68b7c31d`

`KeloCharacterAppearance` consumed `KeloPvPCastMovementPrediction.active` and preserved combat aim for the entire cast timeline.

Chromium result on mobile and desktop:
- windup: UP / combat-aim
- active: UP / combat-aim
- recovery: UP / combat-aim
- movement continued during the cast

AGENT B VERDICT: EMPATA.
Reason: targeting/readability was fixed during startup and impact, but the whole 180 ms Fireball recovery remained visually pinned to aim even while movement continued. That made post-impact locomotion visually overcommitted.

## CANDIDATE B — WINNER
Gameplay commit: `80f21bcd7331cfeefbbf4c79fc8e887e37538dfa`
CI/winner-lock commit: `32c2caa625ea2edfc186c054e90d9d86b81dac40`

Refinement in the same owner only:
- cast aim-facing is committed during `windup` and `active`
- at `recovery`, presentation returns immediately to the existing locomotion-facing row
- no movement, collision, ability damage, hit geometry, cooldown, camera, server authority, or networking behavior changed
- no new engine/manager/wrapper was introduced

Strict Chromium result, both mobile and desktop:
- before cast: RIGHT / movement
- windup: UP / combat-aim
- active: UP / combat-aim
- recovery: RIGHT / movement
- diagonal movement remained active throughout
- travel during sampled cast window: ~24.09 px mobile, ~24.11 px desktop
- page errors: 0

AGENT B VERDICT: GANA.
Primary perceptual improvement: the character visually acknowledges the attack direction through anticipation/impact, then releases back to travel direction instead of remaining visually locked after impact.
