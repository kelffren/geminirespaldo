### PROBLEM
Kelo World already has a presentation contract that separates physics/collider geometry from visual geometry and publishes `nameplateAnchorX/Y`, but the LIVE identity nameplate renderer does not consume that anchor. `src/ui/player-nameplate.js` recomputes vertical placement from `actor.y - actor.radius - 19`. This makes nameplate clearance depend on the small gameplay collider rather than the actual avatar top. The mismatch becomes more visible and more dangerous as avatar visual scale increases from 1.15x toward 1.20x, and when appearance layers such as hair/helmets/capes extend above the base sprite.

### CONFIRMED_IN_GEMINI
1. Current `main` runtime loads `engine-ab.js`, `src/characters/character-appearance.js`, then later `src/ui/player-nameplate.js` through KeloAvatar middleware.
2. `engine-ab.js` publishes `KELO_AVATAR_PRESENTATION.get(actor, face)` with `footRoot`, `visualTop`, `visualHeight`, and explicit `nameplateAnchorX = footRootX`, `nameplateAnchorY = footRootY - visualHeight - 6`.
3. `character-appearance.js` already consumes the presentation contract and uses `layout.nameplateAnchorX/Y` for its own legacy/simple name drawing path.
4. The identity-aware `KeloActorNameplate.draw(actor)` instead computes `x = actor.x`, `radius = max(12, actor.radius || 20)`, and `baseY = actor.y - radius - 19`; it does not query `KELO_AVATAR_PRESENTATION` and therefore ignores visual scale and visual top.
5. `KeloActorNameplate` is middleware priority 500 and draws nobility/name/title after downstream avatar rendering. Therefore this is the authoritative identity stack users see when loaded, and it can disagree with the appearance contract beneath it.
6. This is not a collider bug. The collider should remain unchanged. It is a presentation-consumer bug/contract mismatch: a UI presentation layer asks physics radius for visual head clearance.

### EXTERNAL_EVIDENCE
- Unity `Sprite.bounds` exposes sprite bounds in world-space units, reinforcing the distinction between rendered geometry and collider geometry when consumers need visual extents: https://docs.unity3d.com/ScriptReference/Sprite-bounds.html
- PixiJS explicitly distinguishes local/global render bounds (`getLocalBounds`, `getBounds`) and supports custom bounds areas when performance matters: https://pixijs.com/8.x/guides/components/scene-objects
- Aseprite issue #1357 documents why per-frame pivots/tagged points are useful for humanoid sprites of different sizes and specifically cites aligning/sorting characters from a foot/root anchor while allowing independent head/attachment points: https://github.com/aseprite/aseprite/issues/1357
- Godot proposal #9222 describes center-bottom pivots as the useful root for Y-sorted 2D characters, again separating ground/root anchoring from sprite extent: https://github.com/godotengine/godot-proposals/issues/9222
- Community counterevidence: screen-space health/name UI can intentionally remain a constant readable size rather than scaling with the world actor. That argues against scaling fonts with Kelo; it does NOT justify anchoring the UI from the collider. Example discussion: https://www.reddit.com/r/godot/comments/13djz5i/

### HYPOTHESIS
If KeloActorNameplate consumes the avatar presentation `nameplateAnchor` (or a future appearance-composed top anchor) while keeping text size screen/world policy unchanged, Kelo can increase visual scale without name/nobility/title drifting into the head. Using a stable appearance-level union/top anchor should also reduce direction-dependent vertical snapping compared with deriving placement from collider radius.

### PROPOSED_CHANGE
Do not change production blindly. Benchmark in stages:
A. Baseline: current `actor.y - radius - 19`.
B. Presentation-anchor: in `KeloActorNameplate.draw`, resolve current face and consume `KELO_AVATAR_PRESENTATION.get(actor, face).nameplateAnchorX/Y`, falling back to current radius math only when the presentation owner is unavailable.
C. Appearance-composed anchor: only if CG-009 alpha/layer bounds prove the base `nameplateAnchorY` can still overlap hair/helmet/equipment, extend the existing presentation contract so the active appearance stack publishes a conservative top/nameplate anchor. Do not add another manager.
D. Optional legibility policy: independently test whether font/stroke size should remain constant, use a small viewport-class adjustment, or cap scaling. Do not couple font scale to avatar scale without evidence.

### DO_NOT_ASSUME
- Do not increase `actor.radius` to move the nameplate; collider geometry must remain gameplay-owned.
- Do not assume `visualTop`/`nameplateAnchorY` is already exact for all modular appearance layers; CG-009 is measuring silhouette accuracy.
- Do not delete the fallback radius path until remote/legacy actors without presentation metadata are verified.
- Do not scale the nameplate text merely because the avatar grows; readable UI and world geometry are separate concerns.
- Do not modify physics, movement speed, camera, collision, stride cadence, or input in this benchmark.

### RISKS
1. `KELO_AVATAR_PRESENTATION` currently uses semantic/static visual dimensions, so B may expose inaccuracies already identified in CG-009. If so, do not revert to collider ownership; proceed to C with measured appearance-composed bounds.
2. A tightly per-frame alpha-derived top anchor can make text bob with arms/hair. Prefer a conservative union-by-direction or stable appearance-level top envelope for UI if per-frame bounds chatter.
3. Modular equipment/hair may extend visual top beyond base hero metrics. The eventual contract must be composable by appearance layers.
4. World-space text can become too small/large under extreme zoom even with a correct anchor. Treat legibility as a separate policy/benchmark.
5. Generic Prop redraws may invoke avatar middleware again; verify identity text is not duplicated in an occlusion redraw path or rendered above props incorrectly.
