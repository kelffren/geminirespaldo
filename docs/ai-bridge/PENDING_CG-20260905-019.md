### PROBLEM
CG-20260905-018 proposed H1: a possible one-simulation-step release visual tail caused by `engine-ah` hard-stopping after `engine-ac` visual-state calculation. After reading the relevant `engine-a.js::updateMovement` implementation in full, that specific H1 is not compatible with the current DIRECT movement configuration and must not be acted on as a fix hypothesis.

### CONFIRMED_IN_GEMINI
- `engine-ac.js` sets `CONFIG.movementType='DIRECT'`.
- `engine-ac.js::updateMovement` computes processed input/gait/speed, then calls its wrapped `_move(dt)`, then calls `updateVisualMotion(...)`.
- In `engine-a.js::updateMovement`, DIRECT mode immediately assigns `localPlayer.vx = input.normX * CONFIG.speed` and `localPlayer.vy = input.normY * CONFIG.speed` before position integration.
- Therefore, on a true release where processed input is already zero, the base movement call sets velocity to zero before `engine-ac` evaluates `spd` and `physicallyMoving`. `engine-ah` subsequently zeroes velocity again, but it is redundant for this normal DIRECT-release path.
- So wrapper order alone does NOT establish a one-tick visual release tail. The release trace proposed in CG-018 remains useful as regression instrumentation, but there is no evidence-based reason to change stop ownership from that hypothesis.
- The stronger unresolved lateral issue remains reversal presentation: on left/right sign reversal, physics changes direction immediately, facing can flip immediately, and the same stride phase/frame is mirrored. Frame-index continuity does not prove support-foot continuity because mirroring swaps the screen-side interpretation of the pose.
- Scale remains 1.15x with collider/footRoot separated, and should still be A/B tested independently.

### EXTERNAL_EVIDENCE

- Adobe walk-cycle guidance emphasizes contact poses and weight transfer; a reversal that visibly changes which foot supports the body without a transfer can look less grounded even if frame index is continuous: https://www.adobe.com/creativecloud/animation/discover/animation-walk-cycle.html
