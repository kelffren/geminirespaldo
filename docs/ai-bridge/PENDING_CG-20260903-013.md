### PROBLEM
Current lateral locomotion preserves `stridePhase` across an immediate RIGHT↔LEFT reversal, which is generally desirable for temporal continuity. However, production LEFT is not a separate authored sequence: `engine-ab.js` uses the same row as RIGHT and mirrors the entire draw around `p.x`. Therefore preserving the same numeric phase/frame while flipping the sprite can instantly exchange which screen/world-side foot appears forward or planted. Phase continuity is not automatically contact-identity continuity.

This matters for the user's current premium lateral target because a reversal can look like a leg teleport/pivot even when the world trajectory, frame index and stride phase are mathematically continuous. Scaling the avatar up makes that silhouette discontinuity more visible.

### CONFIRMED_IN_GEMINI
At current main baseline `a2cd6d80f13c6045a62f2e576b59cf47be66482e` / index title Kelo World V6.16:

1. `engine-ac.js` stores one continuous `v.stridePhase`; when movement remains on it advances from actual world distance and does not reset merely because face changes.
2. `v.frame = floor(v.stridePhase * 4) % 4`; the same frame index survives an immediate horizontal reversal unless another stop/reset condition occurs.
3. Facing is recomputed from `v.dx/v.dy`; an immediate sign change in horizontal movement changes `v.face` from right to left or vice versa.
4. `engine-ab.js` selects row 2 for both LEFT and RIGHT.
5. LEFT is synthesized by `translate(p.x) -> scale(-1,1) -> translate(-p.x)`; RIGHT is the unmirrored row 2.
6. Therefore a right-facing frame and left-facing frame with identical `frame`/`stridePhase` are exact horizontal mirrors of the same authored pose, not two independently contact-authored poses.
7. Existing code has no metadata for `leftFootPlant`, `rightFootPlant`, contact marker identity, reversal pose, or phase remap on direction change.
8. Physics/collider remain independent (`localPlayer.radius=20`); this investigation requires no physics change.
9. `ENGINE_MAP.md` remains stale about hero ownership (it lists engine-m.js as LIVE hero while current production PNG override is in engine-ab.js), so current code is the authority.

### EXTERNAL_EVIDENCE
Epic's current Unreal Engine Sync Groups documentation explains that raw normalized-time continuity is insufficient when locomotion cycles differ in foot placement; marker-based synchronization exists specifically to preserve meaningful events such as foot contacts when blending walk/run and start/stop animations. The relevant lesson for Kelo is semantic contact continuity, not importing Unreal's system wholesale.

Godot issue #86868 provides counterevidence against assuming a visual horizontal flip is semantically free: mirroring a 2D skeleton with scale.x=-1 can invert dependent IK behavior. Kelo does not use IK, so the specific bug does not transfer, but it demonstrates that geometric mirroring can alter directional semantics beyond frame index.

Godot issue #91212 documents visible problems when switching between run-turn/idle/turn states and flipped turn animations, reinforcing that direction-change transitions need explicit semantics rather than assuming immediate animation state changes always look correct.

A recent Unity community foot-placement discussion also calls out stand-still pivot foot sliding as a remaining visible defect even in a system designed to improve grounding. This is anecdotal, not authoritative, but it is directly relevant counterevidence: a system can look grounded during forward travel yet still fail during pivots/reversals.

### HYPOTHESIS
The current numeric phase continuity is probably better than resetting every reversal, but it is not sufficient for premium lateral reversals. The correct solution depends on actual atlas semantics:

- If row 2 frames are approximately bilaterally symmetric contact poses, current mirroring may already be acceptable.
- If frames encode a clear planted/leading foot, identical-phase mirroring likely swaps visible foot identity at reversal and creates a silhouette/contact pop.
- If the unused row 1 is a true LEFT sequence, it may preserve authored foot identity better than mirroring, but only after the row is visually audited.
- A future 8+8 WALK/RUN atlas should encode contact markers explicitly so a reversal can map phase by foot identity rather than by raw normalized phase.

No production change is recommended until the current four lateral frames are classified.

### PROPOSED_CHANGE
P1 — Do not reset stride phase on reversal as a blind fix.

P2 — Build a contact-semantic table for the current lateral frames. For each row-2 frame, label if visually possible: `leftPlant`, `rightPlant`, `doubleSupport`, `passing`, or `unknown`. Perform the same audit for row 1 before deciding whether it is usable as authored LEFT.

P3 — Compare reversal policies with identical physics traces:
A. BASELINE: same phase/frame, immediate mirror.
B. CONTACT_IDENTITY_REMAP: on RIGHT↔LEFT reversal, select the phase/frame that preserves the same planted physical foot where the atlas supports it.
C. NEAREST_DOUBLE_SUPPORT: if contact identity cannot be preserved cleanly, snap only the presentation to the nearest double-support/neutral reversal pose for a very short bounded settle; do not delay physical reversal.
D. AUTHORED_LEFT: only if row 1 is verified as a true compatible LEFT sequence, compare direct LEFT against mirrored row 2 with contact markers aligned.

P4 — Future atlas manifest should carry semantic markers, e.g. per gait/direction: contact phase(s), left/right plant identity, neutral/double-support pose, pivot and foot root. Do not encode this as magic frame-number assumptions in `engine-ac.js`.

P5 — Keep collider, world movement, camera and stride-distance accumulation unchanged in the first A/B. This is presentation-only.

### DO_NOT_ASSUME

### RISKS
- Contact remapping can itself create a larger silhouette pop if the four-frame atlas has no semantically corresponding pose.
- A neutral reversal snap can feel robotic if overused or held too long.
- Mirrored row 2 may be artistically intentional and visually adequate; do not replace it merely because row 1 exists.
- A true authored LEFT row can still be worse if pivots/contact timing differ from RIGHT.
- Larger avatar scale amplifies both genuine foot-contact problems and harmless single-pixel silhouette differences, so compare at current size first.
