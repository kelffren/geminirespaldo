### PROBLEM

The current local visual locomotion state uses a 75 ms stop hold, but during that hold stride advancement has already stopped. This can freeze whichever walk/run frame happened to be active at release and then abruptly reset to frame 0 when the hold expires. If the frozen frame is a passing/up/extreme pose rather than a planted/contact pose, the character can visually hover or snap into idle even though physics stopped correctly. This becomes more visible as the avatar is enlarged.

### CONFIRMED_IN_GEMINI

At base commit `0ee5f019...`, `engine-ac.js` defines `VISUAL_STOP_HOLD_SEC = 0.075`. `updateVisualMotion()` sets `v.on=true` while `stopElapsed < 0.075`, but `v.lastStepDistancePx` is zero whenever per-update displacement is not greater than `MIN_VISUAL_MOVE_PX=0.12`. When `v.on` is true and no credited step distance exists, the code does not advance `stridePhase` or `frame`; it simply preserves the previous frame. When the 75 ms hold finally expires, the `else if (!v.on)` branch resets `stridePhase=0`, `strideDistancePx=0`, and `frame=0` in one update. Therefore release behavior is currently: last moving pose freezes for up to ~75 ms, then hard reset to frame 0.

`engine-ab.js` directly consumes `m.frame` for the local hero and draws that atlas column. When `m.on` becomes false it resolves to column 0. There is no separate stop state, contact selection, stop pose, foot-side state, or authored transition map. `hero.PNG` is still treated as a 4-column gait sheet.

This is separate from CG-20260903-020 (lost subpixel stride credit), CG-20260903-021 (physical reversal policy), CG-20260903-022 (visual bounds/depth root), CG-20260903-023 (subpixel/sampling), CG-20260904-001 (contact shadow), and CG-20260904-002 (diagonal facing hysteresis). It should not reopen those items unless benchmark interaction is demonstrated.

### EXTERNAL_EVIDENCE

Official Unreal Engine animation documentation treats locomotion starts/stops as transition/synchronization problems rather than arbitrary frozen-frame holds. Unreal Sync Groups/Markers explicitly call out walk/run starts and stops and recommend synchronizing around meaningful foot markers when stride lengths/cycles differ. Unreal also recommends related locomotion animations use compatible planted-foot timing to avoid visible play-rate/pose pops.

Godot AnimationTree exposes explicit Immediate, Sync and At End state-transition modes plus reset/crossfade behavior, reinforcing that leaving locomotion is normally an authored transition policy rather than merely freezing the source pose for a fixed wall-clock delay.

Community animation feedback consistently identifies contact/down/passing/up as semantically different poses and emphasizes that the weight-bearing foot should not slide. This is useful supporting evidence, but not authority over Kelo's actual four frames: the current `hero.PNG` must be classified before assuming which columns are contacts.

Counterevidence: an immediate reset to frame 0 can be the best choice for a tiny 4-frame pixel sprite if column 0 is intentionally authored as both neutral/contact and the stop is visually clean. A 75 ms hold can also suppress noisy idle↔walk flicker. Therefore do not remove the hold solely because a state-machine engine offers more sophisticated transitions.

### HYPOTHESIS

The stop problem is not primarily the 75 ms duration; it is that the hold is pose-agnostic. A premium result may come from preserving input/physics semantics while making the presentation settle onto a semantically planted frame before idle. If the atlas has no usable planted frame, the correct result may be a shorter immediate reset or a future authored stop/contact frame instead.

### PROPOSED_CHANGE

Do not implement blindly. First classify all four lateral columns for RIGHT and mirrored LEFT using the actual asset as `contact/planted`, `passing`, `up/extreme`, or `unknown`.

Benchmark these presentation-only candidates with identical world/camera traces:

A — BASELINE_FREEZE_SNAP: current 75 ms frozen last frame, then frame 0.

B — IMMEDIATE_IDLE: when physical movement and valid movement intent both end, reset visual frame/phase to idle immediately; no stop hold for pose, while any input-noise debounce is handled separately.

C — CONTACT_SETTLE: on release, choose the nearest valid planted/contact column (or the planted side consistent with current stride phase), hold that pose briefly, then idle. Do not advance world position or fabricate stride distance.

D — PHASE_AWARE_SHORT_SETTLE: only if classification supports it, allow a bounded presentation-only settle of <= one atlas step toward the nearest planted pose, with a strict max duration candidate matrix such as 16/32/48/64 ms. Reject if this produces leg motion while the body is stationary that reads as foot skating.

Architecturally, separate `stopDebounce` from `stopPosePolicy`. `VISUAL_STOP_HOLD_SEC` currently does both jobs implicitly.

### EXPERIMENT

1. Record exact HEAD/build and capture the four RIGHT lateral source cells; mirror semantics for LEFT only after verifying mirroring preserves pose meaning.
2. Manually/visually classify each lateral column: planted/contact candidate, passing/up/extreme, unknown. If classification is ambiguous, mark it and keep candidates B/C conditional.
3. Freeze camera and run deterministic lateral traces at processed magnitudes 0.30, 0.60, 0.699, 0.80, 1.00: idle→RIGHT steady→release, then mirrored LEFT. Trigger release while each of the four columns is active, at least 20 samples per starting column.
4. Log release timestamp, last moving frame, stridePhase, `lastStepDistancePx`, `stopElapsed`, displayed frame each update, first idle frame timestamp, and world distance after release.
5. Compare A/B/C and, only if necessary, D with identical recorded movement traces.
6. Repeat the winning policy at 60/90/120 Hz-equivalent browser presentation, recording actual update cadence rather than assuming update==refresh.
7. Repeat with visual scale 1.00x, 1.15x and 1.25x after physics/presentation-scale separation is available; collider remains 20.
8. Run near-wall/corner countertests to ensure collision micro-corrections do not create repeated stop-settle triggers.

### RISKS

- If frame 0 is not a true idle/contact frame, B can worsen the pop.
- C can choose the wrong planted foot if current four-frame art does not encode foot identity clearly.
- D can create an in-place leg twitch that reads worse than the baseline.
- A short hold may currently mask joystick noise; separating debounce from pose policy must preserve input stability.
- CG-020 can contaminate low-speed stop timing by discarding small distances, so first conclusions should prioritize stable speeds where stride credit is reliable.
- Enlarging the sprite magnifies pose pops, but scale should not be changed in the first causal test.
