### PROBLEM
The LIVE locomotion state resets idle/release to plantFrame=2 and plantPhase=0.5. On the next movement onset, stridePhase does not jump to an immediate departure/contact pose; it advances only from achieved world distance. Because frame selection is floor(stridePhase*4), frame 2 remains visible until phase reaches 0.75. The actor can therefore translate one quarter-cycle before the first visible lateral frame change. This is distinct from CG-042 steady-state foot slip and from CG-036 per-update epsilon loss: it is an onset-phase/pose-latency problem.

### CONFIRMED_IN_GEMINI
Current main at BASE_COMMIT still declares Kelo World V6.33. engine-ac.js defines DEFAULT_PLANT_FRAME=2, PLANT_PHASE=0.5, WALK_CYCLE_WORLD_PX=50, RUN_CYCLE_WORLD_PX=90 and on idle sets stridePhase=PLANT_PHASE, strideDistancePx=0, frame=PLANT_FRAME. On movement, frame changes only after accumulated accepted distance advances stridePhase across the next 0.25-cycle boundary. cycleWorldPxFor() yields 50 px for walk and 50→90 px across run magnitude 0.70→1.00. speedFor() plus targetSpeed=mag*speedCap gives approximately: mag 0.50 => 55.16 world px/s; mag 0.70 => 97.32; mag 1.00 => 185.28. Therefore the distance before frame 2 can become frame 3 is 12.5 px at mag 0.50/0.70 and 22.5 px at mag 1.00, corresponding to about 227 ms, 128 ms and 121 ms respectively, before considering the separate MIN_VISUAL_MOVE_PX issue. At mag 0.10, the theoretical quarter-cycle hold is about 1.14 s; at mag 0.05 about 2.27 s, and CG-036 can make it worse at high refresh. engine-ab.js consumes _visualMotion.frame directly through stepCol() and uses the same lateral row while moving, so this is a visible pose hold, not merely audit state. scripts/live-hero-audit.mjs currently waits 220 ms before its first RIGHT sample, so it can miss almost the entire onset defect at full run and is too late to characterize the first 200 ms.

### EXTERNAL_EVIDENCE
Unity's Blend Tree documentation states that locomotion clips blend best when foot-contact moments are aligned in normalized time, explicitly using left/right foot contacts as phase landmarks. Unity's navigation/animation coupling documentation also recommends responsive idle↔move transitions around 0.10 s and notes that locomotion animation choices are used to prevent foot sliding. Godot's AnimationTree supports cyclic phase synchronization for locomotion and Carry mode to retain play position when switching discrete 2D frame animations, showing that phase continuity/transition policy is an explicit animation responsibility rather than something to leave accidental. Community reports in GameMaker describe a directly analogous symptom: tapping movement can make the character slide in an idle/plant pose when the walk animation does not depart quickly enough. Counterevidence: always forcing the first walk frame on every tap can create repetitive same-foot starts and destroy continuity; a GameMaker discussion specifically notes that resetting to a fixed first step makes repeated taps always lead with the same foot. Therefore the desired fix is not blindly frame=0 on every onset.

### HYPOTHESIS
Kelo's lateral movement will feel more planted and premium if locomotion onset uses an explicit departure-phase policy that produces a visible support-to-push-off change within roughly 60–120 ms while preserving alternating-foot continuity across short stops. A small presentation-only onset state or phase nudge may solve this without changing physics, world trace, collider, camera or steady-state stride cadence.

### PROPOSED_CHANGE
Do not change production yet. First instrument onset. Candidate A for QA only: when transitioning visualOn false→true after a sufficiently long idle, initialize to an authored departure phase adjacent to the plant pose rather than waiting a full quarter-cycle of world travel. Candidate B: preserve a remembered next-foot/half-cycle bit across release so repeated taps alternate support foot instead of always restarting the same leg. Candidate C: add a very short presentation-only start transition (one authored departure frame, <=100 ms) while the existing distance-driven stride continues underneath, then hand off at a phase-consistent boundary. Keep physics DIRECT and unchanged during these candidates.

Run deterministic input magnitudes 0.10, 0.25, 0.50, 0.69, 0.70, 0.80, 1.00 for at least 5 starts each at effective 60/90/120 Hz. Negative controls: stationary input=0, movement against a wall, immediate RIGHT→LEFT reversal, and diagonal onset.

### RISKS
Forcing an onset pose can create a visible frame pop if the authored frame is not adjacent to plantFrame=2. Preserving next-foot state can look wrong after long idle if body orientation changed. A timed start clip can desynchronize from achieved world distance if handoff is not phase-matched. At very low analog magnitude, a fast pose change with almost no translation may look like feet churning; therefore magnitude-aware onset policy may be needed. CG-036's per-update distance epsilon can confound 90/120 Hz results and must be logged rather than silently mixed into this change.
