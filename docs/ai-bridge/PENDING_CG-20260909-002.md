## CG-20260909-002 — Current transform offsets move the foot-root itself; do not reuse them for locomotion bob/lean without a grounded pose-space contract

### PROBLEM
Kelo World is preparing premium lateral locomotion with foot planting, subtle body lean, vertical/horizontal bob and a larger avatar. The current generic transform path applies `offsetX/offsetY` as a translation of the entire actor canvas before rotating/scaling around the foot pivot. Therefore the offset translates the rendered foot-root itself. That is acceptable for an intentional whole-body/root displacement, but it is the wrong primitive for a grounded locomotion bob/sway whose support foot should remain planted. Reusing the existing transform offset for walk/run bob would visually move the feet and any actor-local FX away from the semantic ground anchor even though physics, `footRoot` and collision do not move.

### CONFIRMED_IN_GEMINI
At current `main` base commit 054f5d403020835627e9c5de192d6cf8cd875433:

1. `src/characters/character-appearance.js` renders the LIVE player relative to a semantic foot root and per-frame authored foot anchors. Its destination is `dx = round(footRootX - anchorX*scale)` and `dy = round(footRootY - anchorY*scale)`. This means the current avatar path already has a strong grounded reference.
2. `src/visuals/animation-system.js` exposes the semantic `foot` / `ground` anchor from `KELO_AVATAR_PRESENTATION`, and transform clips contain `scaleX`, `scaleY`, `rotation`, `offsetX`, `offsetY`.
3. `src/visuals/visual-integration.js` samples the winning transform, gets the foot pivot, then performs the operations in this order: `translate(offsetX, offsetY)` -> `translate(pivot.x,pivot.y)` -> rotate -> scale -> `translate(-pivot.x,-pivot.y)` -> render back FX -> `next()` (avatar) -> front FX. Because the translation occurs before the pivot transform, a nonzero `offsetX/offsetY` moves the pivot/foot-root on screen by that offset as well.
4. Existing action clips prove this is active data, not dead code. `cast_magic_01` includes `offsetY=-1` and `offsetX=2`; `cast_self_01` includes `offsetY=2`.
5. No dedicated locomotion bob/lean clip is currently present in `visual-manifests.js`; therefore this is a forward architectural hazard rather than a claim that current lateral locomotion already bobs incorrectly.
6. `engine-ac.js` remains owner/support for gait/stride and correctly advances stride from resolved world distance. It should not gain another render wrapper or own Canvas transforms.

### EXTERNAL_EVIDENCE
Official Unity root-motion documentation separates the world/root trajectory from pose-relative motion. It explicitly notes that root Transform Position Y can be kept constant while vertical motion remains in the pose, and that a Feet-based root reference keeps blending around the lowest foot to prevent floating. This supports separating grounded pose motion from actor/root displacement rather than representing both with one translation primitive.

Epic's official Speed Planting workflow pins IK goals when feet should be planted, specifically to eliminate visible foot sliding. Although Kelo is 2D and does not need full IK, the transferable principle is that body motion must not implicitly drag a support foot that is supposed to be planted.

Community evidence is consistent but not authoritative: Godot/gamedev discussions repeatedly report jitter/sliding when idle/body/root motion feeds back into foot placement; one commonly reported mitigation is to keep the grounded foot target stable while body/hip motion happens above it. Another 2D discussion points out that changing sprite/body motion around a center pivot can make feet sink/float, while a bottom/foot reference or a separate display transform avoids coupling the collider/root to presentation.

Counterevidence: not every vertical offset should preserve the feet. Jump, knockback, levitation, authored recoil, a hop, or an ability that physically/visually lifts the whole actor may legitimately move the foot/root. Therefore the proposal is NOT to delete `offsetX/offsetY`; it is to distinguish root displacement from grounded pose displacement.

### HYPOTHESIS
For lateral walk/run, Kelo will look more planted if future bob/lean/sway is expressed in a grounded pose-space whose invariant is `supportFoot/footRoot stays fixed`, while explicit root-displacement effects retain the existing whole-actor translation semantics. This should improve perceived weight without changing physics, collision, camera or world traces.

### PROPOSED_CHANGE
Do not implement blindly. First instrument and compare the current transform semantics.

If the benchmark supports the hypothesis, extend the existing animation/visual owners instead of creating a new animation manager. Preferred conceptual split:

- `rootOffsetX/rootOffsetY` (or existing `offsetX/offsetY` retained as root offset): moves the entire avatar/foot root intentionally.
- `poseOffsetX/poseOffsetY` or an equivalent grounded body-local transform: moves/leans the body presentation while preserving the semantic foot/root contact.
- rotation/scale for grounded locomotion continue around the foot pivot.
- contact shadow/ground FX consume the unmodified ground anchor and must not inherit pose bob.

For a raster sprite with no skeleton, a grounded vertical bob cannot literally move only the torso unless the art/layers support it. Therefore a first candidate may be micro-rotation + scale around foot pivot, or a very small pose translation with an explicit compensating foot-anchor translation, but this must be measured against the actual opaque foot centroid. Do not fake IK complexity that the current sprite cannot support.

### DO_NOT_ASSUME
- Do not assume any nonzero body bob is automatically better.
- Do not assume existing action offsets are bugs; they may intentionally move the whole actor.
- Do not alter `localPlayer.x/y`, collider radius, collision resolution, camera target or network state for a presentation-only test.
- Do not add another `renderAvatar` wrapper or movement owner.
- Do not combine this benchmark with avatar 1.20x, cadence changes, camera changes or CG-20260909-001 in the same A/B measurement.
- Do not infer foot planting solely from the semantic pivot; measure the visible opaque foot-contact centroid.

A — current transform baseline.

Instrument Canvas transform and avatar presentation during idle/RIGHT/LEFT/reversal using no locomotion transform. Then use a debug-only transform clip with deliberately exaggerated values to make semantics unambiguous:
- test root offset: `offsetY = -4`, no rotation/scale;
- test foot-pivot lean: rotation +/-0.025 rad, no offset;
- test scale/breath: scaleX/scaleY around foot pivot, no offset.

Capture:

3. visible/opaque foot-contact centroid if the audit can precompute it;
4. current Canvas matrix immediately before Character Appearance draw;
5. contact shadow anchor if/when CG-098 is implemented;
6. world/collision/camera traces.

B — grounded candidate, only after baseline: preserve foot-root on screen while applying an equivalent presentation effect above it using existing owners. Do not change physics.

Reproduce idle, RIGHT 2 s, LEFT 2 s, RIGHT<->LEFT reversal, release-to-plant, wall-block hold, and diagonal wall slide. Repeat time-sensitive captures at 60/90/120 Hz and at 390x844 DPR2 + desktop 1280x720 DPR1.

After B is stable at current avatar scale, repeat only the winning candidate at 1.20x to verify that the larger avatar does not amplify foot drift.

Initial gate for a grounded pose transform: semantic foot-root drift <= 1 CSS px P95, no measurable physics/camera trace change, no duplicate render owner, and a clear visual preference over no bob/lean. If the sprite cannot support grounded bob without visible deformation or foot drift, reject bob and keep only foot-pivot lean/scale or authored sprite frames.

### RISKS
- A compensating translation can introduce subpixel/rounding shimmer because Character Appearance already rounds destination coordinates.
- Applying body-only transforms to modular equipment may expose the double-transform/ownership issue identified in prior research; verify the current middleware stack before implementation.
- Actor-local FX currently inherit the same transform as the avatar; splitting root vs pose space may require each FX type to declare whether it follows body or ground.
- Large bob amplitudes will look floaty even if mathematically anchored.
- A 1.20x avatar magnifies one-pixel residuals and can make previously invisible foot drift obvious.
